# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

didierkrux.com, Didier Krux's portfolio with a 3D Meebit and (soon) a voxel world. Astro static site on Vercel with one React island. The design spec lives in `docs/superpowers/specs/` and the phase plans in `docs/superpowers/plans/` (both gitignored, ask Didier for them if missing).

## Commands

    pnpm dev              # dev server at http://localhost:4321/
    pnpm build            # freshness check for the resume PDF, then astro build
    pnpm check            # astro type check
    pnpm test             # Vitest unit tests (src/**/*.test.ts, scripts/**/*.test.mjs)
    pnpm vitest run -t "name"   # one test by name
    pnpm test:e2e         # Playwright; builds and serves dist on port 4399 itself
    pnpm test:e2e --project=desktop tests/e2e/navigation.spec.ts   # one spec, one device
    pnpm import:episodes  # digitalkrux.com/api/episodes.json -> src/content/episodes.json (run when a new set is out; EPISODES_API=<url or local path> to override)
    pnpm resume:pdf       # /resume -> public/Resume_Didier_Krux.pdf (2 or 3 full A4 pages)
    pnpm og:images        # /og/{home,world} -> public/og/*.png
    pnpm import:animations # fetch clips listed in src/lib/animations.json that are missing from public/anims

Generated files (episodes JSON, PDF and its meta, OG PNGs) are committed; regenerate and commit them when their sources change. Tests and scripts serve `dist/` with `scripts/lib/serve-dist.mjs`, never `astro preview`: Astro 7 detects agent environments and backgrounds its preview server, which Playwright cannot supervise. The Astro dev toolbar is disabled in `astro.config.mjs`. Playwright runs with `reducedMotion: 'reduce'` so scroll-position assertions do not race smooth scrolling.

## Git rules

Never commit or push. Didier reviews and commits himself. Work happens on the `rebuild` branch; `master` is production until the rebuild is merged. `digitalkrux` is a separate site with its own repo; the only thing this project needs from it is the `/api/episodes.json` endpoint its `convert.cjs` writes at build time, so keep changes there to that. `archive/2018-site/` is the previous site, kept for reference, never deployed or imported.

## Structure

- **One scrollable page** at `/`: the intro (name, bio, resume PDF, links) first, then three sections in this order: `#web3`, `#web2`, `#projects`. Every project is a card in the DOM with its full story visible; nothing is hidden behind pagination or a read-more. `/world` is one scrolling page in four parts (DJ booth, Meebit, Poses, Places, each a `[data-world-panel]` with its id as hash) under a sticky bar of links; `src/lib/world-tabs.ts` scrolls to a part on click (through `scrollToElement`, allowing for the bar's height), names the part in view from the scroll position and keeps it in the URL hash, `/resume` the print view, `/manual` the key list and asset credits.
- **Music.** The Meebits Turn On album (22 tracks, CC BY, files in `public/audio/turn-on/`, 83 MB) plays quietly through the header player on every page; off by default, Space is play/pause for whatever is loaded, → and ← skip within the active playlist (album tracks, or the sets while one is loaded; a finished set runs on to the next), ↑ and ↓ walk the projects, the transport state is remembered in `dk:sound`. The world's DJ booth (`/world`) has two decks side by side: Digital Krux sets on the left (`[data-set-url]`, set deck) and the 22 Turn On tracks on the right (`[data-track-index]`, ambient deck through `playTrack`); each deck has its own readout and seek bar, scoped with `data-now-playing`, `data-seek` and `data-time` set to `set` or `track` (unscoped controls, like the header's, follow whatever plays). DJ mode is not a setting, it is the state while a set plays (`dj` store set by `playSet`/`stopSet` only). No music tab, no career timeline (resume only).
- **Keys and gestures.** 1 scrolls to the top (labelled gm), 2, 3, 4 jump to Web3, Web 2.0, Projects, 5 enters or leaves the world; ↑ and ↓ walk projects (on `/world` they step through poses); Space toggles the music; → and ← move to the next and previous track; D Digital Krux mode (the latest set plays, press again to stop); T theme; M next Meebit; ? manual. There is no Esc binding; the `back` action remains for the site-name link and the manual's close button. On desktop the header bar shows only 1 to 5 and ?, highlighting the current section (5 on `/world`); arrows, Space, D, T and M work everywhere but are listed only in the manual. On touch and narrow screens the same key bar sits in a fixed bottom bar (hint words only, no keycaps and no ?, the current one in the accent), the stage is a sticky band at the top (`--stage-h-mobile`, about a third of the screen) with the header transparent over it, and the content scrolls under the stage. Horizontal swipe moves between projects; vertical swiping is plain scrolling.

## Architecture

- **Content is data.** Every text lives in `src/content/` as YAML (projects, roles, education, profile, copy, places, credits, skills) or generated JSON (episodes, fetched by `scripts/import-episodes.mjs` from the JSON API that the digitalkrux site generates in its `convert.cjs` build step; the sibling repo's markdown is never read directly). Schemas are in `src/content/schema.ts` (zod v4 via `astro/zod`), registered in `src/content.config.ts`, and unit-tested against the real files in `src/content/schema.test.ts`. Project order: `orderProjects` in `src/lib/content.ts` groups web3, web2, side, each group by explicit `order` then newest start. Voice: web3 native, first person, short, English only, no em dashes. YAML gotcha: a list item containing `: ` must be quoted.
- **Operating model.** Input goes through `src/lib/keymap.ts` (keys, with `worldOnly` and `section` metadata), `src/lib/gestures.ts` (swipes), and `data-action` attributes (clicks) into named actions in `src/lib/actions.ts`; the pure `applyAction` returns new state plus effects (`navigate`, `scrollSection`, `scrollItem`) that `boot.ts` executes. `src/lib/page-controller.ts` tracks the current section and project from scroll position with IntersectionObservers plus a settle pass on scroll (deciding from live geometry, never from the delivered entries, which can be stale), measured against a landing offset read from the layout itself (`landing`: the bottom of the header and, when it spans the content, of the stage band, plus a small gap), which is also what `scrollTo` uses to compute the target position (not `scrollIntoView`, which ignores scroll margins in some mobile browsers), so the pick matches where 1 to 4 and the arrows land, and highlights the keys in both bars.
- **Persistent 3D stage.** `src/components/Stage.tsx` is the one React island (`client:load transition:persist` in `Base.astro`). It loads one of Didier's Meebit VRMs (`public/meebit/<tokenId>.vrm`, roster in `profile.meebits`, choice in the `meebit` store and `dk:meebit`; M cycles, and the Meebit section on `/world` lists them as `[data-meebit-pick]` buttons, pressed state synced by `mountMeebitPicker`) with three-vrm inside React Three Fiber, frames the character from its bounding box, and animates it with Mixamo clips: skeleton-only glTF files in `public/anims/` (the way meeb.cam ships them) retargeted onto the VRM at load by `src/lib/retarget.ts` (port of pixiv's humanoidAnimation example, VRM 0.x axis flip included) and layered by `src/lib/rig.ts` (looping idle, additive upper-body gestures, full-body actions with eased crossfades). `src/lib/animations.json` is the full catalogue (113 clips in 10 categories, meeb.cam's ids and file names; `pnpm import:animations` fetches missing files). `src/lib/anims.ts` reads it and defines the mood pools: `greet` on the intro (wave hello first, then wave hey, bow 1, bow 2, each played once over the idle whenever gm comes into view), `work` in the sections (talk, thumbs up, a look, a laugh between calm idles, one step per project) unless the current project names its own clip (`pose` in its YAML, rendered as `data-pose` on the card, published by the page controller in the `itemPose` store, validated against the catalogue in `anims.test.ts`), which then plays instead, looping when its category loops, and is kept while a set plays (only the scene dances; cards without a clip get the dance pool), `look` on `/world`, `dance` (every dance) while a set plays. All clips are retargeted in place (hips pinned over the origin, height kept). Idle-category clips are the rig's base layer; everything else is an action, looping for dance, motion, pose and performance, once for the rest. The world tab lists the whole catalogue (`[data-anim]` buttons, `src/lib/poses.ts`; no separate auto button): a pick sets the `manualClip` store, which wins over the mood until the same pick again or a page change; `clipPlaying` publishes what runs so the buttons stay pressed. Clicking the character or the pose chip under it cycles the current pool, and so does every project change (arrows, swipe, scroll); `data-clip` on the figure names what plays and `clipName` labels it. While a dance runs the camera eases back so floor moves stay in frame. Head and neck still follow the pointer on top of the clip, and the head nods when music plays without a dance. The mood is exposed as `data-mood` with no visible caption. Behind the character the `Sky` layer (`.stage-sky`) holds a starfield and the glow of the disco ball; in the 3D scene, `Gems` places smooth Ethereum diamonds (`src/lib/eth-shape.ts`, an elongated octahedron with a corner toward the camera, no gap, the four faces toward -x in a lighter tone and the four toward +x in a darker tone of one accent) in the two accents, two at rest and four while a set plays, `Invaders` a rank of voxel invaders (`src/lib/invader.ts`, both classic frames), one at rest and three while a set plays, both placed as a share of the visible width at their depth, `DiscoBall` a faceted mirror ball in the upper left corner, lower and smaller on the wide phone band so it stays out from under the header (metal material reflecting a `RoomEnvironment` map, a glow sprite, a point light inside, and a shell of colored glint points turning the other way for the spots it throws), shown only while a set plays (at rest the centered CSS halo `.sky-moon` stands behind the character and fades while the ball is out), and `ClubLights` three colored spots above the stage that take turns flashing and sweep the character while a set plays. The `Floor` is a perspective grid of 14 by 8 cells (`.stage-floor`, per-cell `--t`/`--d` from the index so server and client agree). All of it stands still until `data-dancing` is true on the figure (a set is playing, or D was pressed): then the diamonds turn and drift, the invaders shuffle and flip frames, the ball spins and shines, the stars twinkle and the cells light up. The CSS parts respect reduced motion. `flat` rendering keeps the voxel colors true. The camera is fitted from the posed skinned bounds (measured a few frames after load, not from the T-pose bind box) so the character fills the column. `public/meebit/still.jpg` is rendered only when WebGL is unavailable, never during loading.
- **Audio.** `src/lib/audio.ts` owns two `Audio` elements: the ambient deck (playlist from the `#ambient-playlist` JSON that `Base.astro` embeds from the `ambient` collection, ordered by `order`) and the set deck (its playlist is the `#sets-playlist` JSON, the same `latestSets` selection the booth renders). `playing` is the transport (something is audible), `setPlaying` says which deck is loaded; DJ mode stays on while a set is loaded, paused included. `playing`, `track`, `setPlaying`, and `progress` stores drive `src/lib/player-controller.ts` (header player with its seek bar, the booth's buttons and per-deck seek bars with elapsed time) and the Meebit's nod. `seek(fraction)` moves whichever deck is active. Actions `play` and `nextTrack` are pure effects executed by the effector in `boot.ts`.
- **Client boot.** `src/lib/boot.ts` runs once per full load, binds keys, clicks (including `[data-set-url]` booth buttons), and pointer gestures, syncs stores from the URL on every `astro:page-load`, and re-applies theme attributes on `astro:after-swap` (the router copies `<html>` attributes from the incoming page).
- **Themes.** CSS variables in `src/styles/tokens.css` under `data-theme="light|dark"`. Both are the Digital Krux podcast palette: magenta `#e737e9` as accent, electric blue as `--accent-ink` (text contrast tint), dark on near-black `#0a0a0a`, light as a white version of the same. `data-dj="on"` (the state while a set plays) changes behavior, not colors: the Meebit dances (a set start clears any hand-picked pose) and the stage sky moves. The resume print view keeps its own violet. Fonts: Chakra Petch (headings, squared but legible), Instrument Sans (text), JetBrains Mono (keys only), Silkscreen (`--font-pixel`). Unbounded and Pixelify Sans were tried and rejected: too round, too hard to read.
- **Touch.** `body` has `touch-action: pan-y` and the stage `touch-action: none`, otherwise Chrome cancels the pointer sequence when it starts scrolling. Rows of inline links must be flex-wrapped: Astro renders adjacent `<a>` elements with no whitespace, which made one row overflow the phone viewport.
- **Cards.** Title, kicker, dates, then a 16:10 screenshot (max 480 px), the full story, tag chips, links. Section headers show the keycap of their shortcut key.
- **Images.** Project previews are 16:10 screenshots in `public/screens/<slug>.jpg`, referenced from each project's `screenshots`. Keep `height: auto` on the img: the `height` attribute otherwise defeats the CSS aspect ratio.
- **Resume.** `/resume` renders explicit A4 page boxes. `src/lib/resume-pack.ts` packs sections into two or three pages and stretches gaps so every page ends at the bottom margin; `scripts/resume-pdf.mjs` prints it with headless Chrome and writes `public/resume.meta.json` with a hash of the sources, which `scripts/check-resume-fresh.mjs` compares at build (warn only).

## Conventions

- Pure logic goes in `src/lib/*.ts` with a sibling `*.test.ts`; nothing in `src/lib` imports `astro:*` virtual modules except `boot.ts`.
- Scripts are ESM `.mjs` in `scripts/`, shared helpers in `scripts/lib/`.
- Third-party assets are listed in `src/content/credits.yaml` and rendered on `/manual`. Fonts are fontsource packages with open licenses. Never copy the Meebits viewer bundle, its fonts, or its animation files.
